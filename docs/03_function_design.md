### 3.1 機能①：物量登録

#### 3.1.1 概要
対象日の入庫・出庫物量を15分単位で登録する。

#### 3.1.2 テーブル定義

**volume_plans（物量計画）**

| カラム名 | 型 | 必須 | 説明 |
|---------|-----|------|------|
| volume_plan_id | UUID | ○ | 物量計画ID（PK） |
| plan_date | DATE | ○ | 対象日 |
| volume_type | ENUM | ○ | 物量種別（INBOUND / OUTBOUND） |
| time_slot_start | TIME | ○ | 時間帯開始時刻（例：08:00, 08:15, 08:30...） |
| volume | DECIMAL(10,2) | ○ | 物量（個） |
| created_at | TIMESTAMP | ○ | 作成日時 |
| updated_at | TIMESTAMP | ○ | 更新日時 |

> ユニーク制約：(plan_date, volume_type, time_slot_start)

#### 3.1.3 画面仕様

**物量登録画面**

- 対象日を選択するカレンダー
- 入庫・出庫タブで切替
- 縦軸：15分スロット（例：08:00〜20:00 → 48スロット）
- 横軸：物量入力欄（数値）
- 行末に「時間合計」列を表示
- ページ下部に「入庫合計/出庫合計」を表示
- 保存・クリアボタン
- CSVインポート機能（列：time_slot_start, volume）

### 3.2 機能②：物量展開

#### 3.2.1 概要
登録済みの物量計画と物量マスタの変換係数を用いて、各工程・15分スロット別の処理量および必要人時を計算する。

#### 3.2.2 計算ロジック

```
【Step 1】工程別処理量の算出
  process_volume[工程][スロット] = volume_plan[入庫 or 出庫][スロット] × conversion_rate

【Step 2】必要人時の算出（15分スロット単位）
  ※ バッファ考慮：前工程から流入するものを累積し、バッファを引いた残を処理する
  
  cumulative_volume[工程][スロット] = 前スロットの残量 + process_volume[工程][スロット]
  
  処理可能量[工程][スロット] = max(0, cumulative_volume[工程][スロット] - buffer_capacity)
  
  required_person_slots[工程][スロット] 
    = 処理可能量[工程][スロット] ÷ (base_productivity × skill_level_rate × (15/60))
  
  ※ skill_level_rate はこの段階では一人前（レベル2, rate=1.0）で計算する。
     実配置時にスキルレベルに応じた補正を行う。

【Step 3】スロットをまたぐ残量の繰越
  carry_over[工程][スロット+1] = cumulative_volume[工程][スロット] - 処理可能量[工程][スロット]
  ただし carry_over ≦ buffer_capacity
```

#### 3.2.3 テーブル定義

**volume_expansions（物量展開結果）**

| カラム名 | 型 | 必須 | 説明 |
|---------|-----|------|------|
| expansion_id | UUID | ○ | 展開ID（PK） |
| plan_date | DATE | ○ | 対象日 |
| process_id | UUID | ○ | 工程ID（FK） |
| time_slot_start | TIME | ○ | 時間帯開始時刻 |
| process_volume | DECIMAL(10,2) | ○ | 工程処理量（個） |
| carry_over_volume | DECIMAL(10,2) | ○ | 前スロットからの繰越量 |
| required_person_slots | DECIMAL(8,3) | ○ | 必要人員数（小数。例：2.5人分） |
| calculated_at | TIMESTAMP | ○ | 計算実行日時 |

#### 3.2.4 画面仕様

**物量展開画面**

- 対象日選択 → 「展開実行」ボタン
- 展開結果を工程別・時間別ヒートマップで表示
  - 縦軸：15分スロット
  - 横軸：工程
  - セル：必要人員数（色の濃淡で可視化）
- 各工程の日合計必要人時を表示
- 「最適化へ進む」ボタン

### 3.3 機能③：人員配置最適化提案

#### 3.3.1 概要
物量展開結果・人員マスタ・条件マスタをもとに最適化アルゴリズムを実行し、3つの配置案を提示する。

#### 3.3.2 提示する3案

| 案 | 名称 | 最適化方針 |
|----|------|-----------|
| 案A | 最速完了案 | 作業完了時刻を最も早くする（コスト・移動は二次考慮） |
| 案B | 最低コスト案 | 作業完了制約を満たしつつ総人件費を最小化 |
| 案C | 最小移動案 | 作業完了制約を満たしつつ工程移動回数を最小化 |

#### 3.3.3 最適化アルゴリズム設計

**アルゴリズム種別：ヒューリスティック（貪欲法＋局所探索）**

50人規模・15分粒度では厳密なMIPソルバーは計算時間が長大になるため、
段階的なヒューリスティックで解を構築し、局所探索で改善する方式を採用する。

```
【共通前処理】
  1. 対象日・対象日の曜日から、出勤可能な人員リストを抽出
  2. 各人員の出勤可能スロット・スキル・時給を準備
  3. 各工程・スロットの必要人員数（volume_expansions から取得）を準備
  4. 工程チェーンを解決し、末端工程の完了期限を把握

【案A：最速完了案の構築】
  1. 末端工程の完了期限に合わせて逆算し、必要人員を前詰めで多めに配置
  2. スキルレベル3（熟練）を優先配置
  3. 残業可能者を終盤スロットに補充
  4. 局所探索：完了時刻を早める方向で配置を改善

【案B：最低コスト案の構築】
  1. 案Aの配置を初期解とする
  2. 完了時刻制約を満たすかチェック
  3. 時給の安い人員から配置（同スキルレベル内で時給昇順）
  4. 残業が発生する配置を削減（残業コスト=時給×1.2）
  5. 局所探索：コスト削減できる配置換えを探索

【案C：最小移動案の構築】
  1. 案Bの配置を初期解とする
  2. 各人員の工程割当を時系列で並べ、切替回数をカウント
  3. 局所探索：同一人員を同一工程に連続配置するよう入れ替え
     （移動回数が減り、かつ完了制約・コストが悪化しない場合のみ採用）

【休憩の挿入（共通）】
  - 各人員の11:30〜13:00の間に60分の昼休憩スロットを確保
  - 昼休憩中はその人員をどの工程にも配置しない
  - 6時間超労働の場合、昼休憩が45分未満であれば別途法定休憩を追加
```

#### 3.3.4 スコア計算

```
【完了遵守スコア】
  = Σ(各末端工程の超過時間) × 大きなペナルティ係数
  → 0 が理想（超過なし）

【総人件費】
  = Σ(人員ごとの（通常労働時間 × 時給 + 残業時間 × 時給 × 1.2）)

【工程移動回数】
  = Σ(人員ごとの工程切替回数)
  ※ A工程 → B工程 → A工程 = 移動2回としてカウント
```

#### 3.3.5 テーブル定義

**optimization_results（最適化結果ヘッダ）**

| カラム名 | 型 | 必須 | 説明 |
|---------|-----|------|------|
| result_id | UUID | ○ | 結果ID（PK） |
| plan_date | DATE | ○ | 対象日 |
| result_type | ENUM | ○ | 案種別（FASTEST / CHEAPEST / LEAST_MOVE） |
| total_cost | DECIMAL(12,2) | ○ | 総人件費（円） |
| total_overtime_cost | DECIMAL(12,2) | ○ | うち残業費（円） |
| total_process_moves | INT | ○ | 総工程移動回数 |
| is_deadline_met | BOOLEAN | ○ | 完了期限遵守フラグ |
| deadline_violations | JSON | - | 超過した工程と超過時間の詳細 |
| calculated_at | TIMESTAMP | ○ | 計算日時 |
| is_selected | BOOLEAN | ○ | 選択済みフラグ |

**optimization_assignments（最適化結果明細：配置詳細）**

| カラム名 | 型 | 必須 | 説明 |
|---------|-----|------|------|
| assignment_id | UUID | ○ | 配置ID（PK） |
| result_id | UUID | ○ | 結果ID（FK） |
| employee_id | UUID | ○ | 人員ID（FK） |
| process_id | UUID | ○ | 工程ID（FK、NULLは休憩） |
| time_slot_start | TIME | ○ | 時間帯開始時刻 |
| slot_type | ENUM | ○ | スロット種別（WORK / LUNCH_BREAK / LEGAL_BREAK） |
| is_overtime | BOOLEAN | ○ | 残業フラグ |
| slot_cost | DECIMAL(8,2) | ○ | このスロットの人件費（円） |

**最適化提案画面**

### 3.4 機能④：シフト生成

#### 3.4.1 概要
選択した最適化案をもとに、人別・工程別のシフト表を生成する。

#### 3.4.2 生成するシフト

**人別シフト**

| 人員名 | 08:00 | 08:15 | 08:30 | ... | 18:00 |
|--------|-------|-------|-------|-----|-------|
| 田中 太郎 | 検品 | 検品 | 検品 | ... | ― |
| 鈴木 花子 | ピッキング | ピッキング | 休憩 | ... | ― |

**工程別シフト**

| 工程名 | 08:00 | 08:15 | 08:30 | ... | 18:00 |
|--------|-------|-------|-------|-----|-------|
| 検品 | 田中、山田 | 田中、山田 | 田中 | ... | ― |
| ピッキング | 鈴木 | 鈴木 | ― | ... | ― |

#### 3.4.3 Excel出力仕様

- シート1：人別シフト表
  - 15分単位のセルに工程名を記入
  - 休憩セルはグレー背景
  - 残業セルはオレンジ背景
  - 人員ごとに実働時間・残業時間・人件費を集計行に表示

- シート2：工程別シフト表
  - 15分単位のセルに配置人員名をカンマ区切りで記入
  - 工程ごとに必要人員数と実配置人員数を対比表示

- シート3：コストサマリ
  - 人員別：通常時間、残業時間、合計人件費
  - 工程別：総人件費
  - 全体合計

#### 3.4.4 画面仕様

**シフト生成画面**

- 選択済みの最適化案のサマリを表示
- 「人別シフト」「工程別シフト」タブで切替表示
- 時間範囲フィルタ（表示開始・終了時刻）
- 「Excelダウンロード」ボタン
- 「再最適化へ戻る」ボタン
