倉庫人員配置最適化システム ユーザーガイド

本システムは、倉庫の1日の作業（入荷・棚入れ・ピッキング・仕分け・梱包など）に対して、 「誰を・いつ・どの工程に配置すれば最適か」をコンピュータが自動で計算し、 日々のシフト（人員配置表）を作成するツールです。

1. アプリの目的とできること

このアプリが解決すること

倉庫では「その日の物量（処理すべき荷物の量）」が日によって変動します。物量に対して 人を多く配置しすぎれば人件費が無駄になり、少なすぎれば作業が締切に間に合いません。 さらに「どの人がどの工程が得意か（習熟度）」「誰が何時から何時まで働けるか」も人ごとに違います。 これらを人手で最適に組むのは非常に困難です。本システムはこの配置決定を自動化します。

主にできること

機能内容
マスタ管理従業員・工程・スキル・物量変換ルール・各種条件を登録・編集できます。
物量登録対象日の物量（時間帯ごとの処理量）を登録します。
配置の自動最適化「最速完了」「最低コスト」の2つの方針で、最適な人員配置を自動計算します。
結果の比較計算エンジン別・方針別に結果（人件費・完了時間・工程移動回数など）を並べて比較できます。
シフト表・稼働グラフ確定した配置をシフト表で確認し、稼働グラフで処理の流れ・滞留を可視化します。

2. アプリ全体のメカニズム

システムは「マスタ整備 → 物量登録 → 最適化計算 → 結果確認」という流れで動きます。

① マスタ整備従業員・工程・条件
→
② 物量登録対象日の物量
→
③ 物量展開工程別・時間帯別へ変換
→
④ 最適化計算配置を自動決定
→
⑤ 結果確認シフト表・稼働グラフ

処理の流れ（工程チェーン）の考え方

倉庫の作業は上流から下流へ流れます。例えば「入荷 → 棚入れ」「ピッキング → 仕分け → 梱包」のように、 上流工程で処理された分だけが下流工程に届きます（15分のタイムラグで伝播）。 システムはこの流れを時間に沿ってシミュレーションし、「届いた分しか処理できない」という 物理制約を守りながら配置を組みます。

入荷生産性100/h
→
棚入れ生産性25/h
ピッキング40/h
→
仕分け35/h
→
梱包28/h
重要：上流の処理が遅れると下流に荷物が「滞留（バッファ）」します。各工程の間にどれだけ 荷物が溜まっているかは「稼働グラフ」で確認できます（→ 第6章）。

3. 各種マスタの意味と登録・管理

最適化の精度は、マスタ（基礎データ）の正確さで決まります。主なマスタは次の通りです。

3-1. 従業員マスタ

働く人の基本情報・勤務条件・スキルを管理します。

項目意味
氏名 / 時給(円)人件費計算の基礎。時給が高い人を早く帰すような最適化に使われます。
曜日ごとの勤務条件曜日別に「出勤/休み」「勤務開始・終了時刻」「残業可否」「最低労働(分)」を設定。
スキル設定（習熟レベル）工程ごとに対応可否と習熟レベルを設定。レベルにより処理生産性が変わります。
習熟レベル生産性意味
レベル180%不慣れ（標準の8割の速さ）
レベル2100%標準
レベル3120%熟練（標準の1.2倍の速さ）

3-2. 工程マスタ・工程接続設定

項目意味
工程名 / ラインタイプ工程の名称と、入庫（INBOUND）／出庫（OUTBOUND）の区分。
基準生産性その工程で1人が1時間に処理できる標準量（例：入荷100個/h、梱包28個/h）。
バッファ容量(個)その工程の前にどれだけ荷物を溜めておけるか（稼働グラフの上限点線）。
工程接続設定「どの工程の次がどの工程か（上流→下流）」を定義。これが処理の流れになります。

3-3. 物量変換マスタ

工程をまたぐと「個数」が変わる場合の変換係数を設定します。例えば「1パレット入荷 → 30個に展開」 のように、上流の処理量を下流の作業量へ変換する係数です。

3-4. 物量登録（対象日の物量）

対象日について、時間帯ごとの物量（個）を登録します。これが「その日の仕事の総量」になります。 最適化はこの物量を、締切までに処理しきれるよう人を配置します。

  • 入庫・出庫はまとめて保存：画面上部の「入庫／出庫」タブで切り替えて入力しますが、 保存ボタンを押すと、その時点で入力されている入庫・出庫の両方が一括保存されます。 タブを切り替えながら入力した内容が保存漏れになることはありません。
  • 数値は直接入力：物量セルは数字をそのままキー入力します（増減の矢印ボタンはありません）。
  • CSVインポート：時間帯・物量のCSVを取り込んで一括入力することもできます。

3-5. 条件マスタ（システム条件）

最適化全体のルールを設定します。条件マスタ ＞ システム条件

条件意味
工程完了期限（定時の目安）各ラインの末端工程（入庫の棚入れ・出庫の梱包）を「残業なしで何時までに終わらせたいか」の目安時刻。処理を強制的に打ち切るハードな締切ではありません。詳しくは第4章の優先順位を参照。
残業時給倍率 / 残業開始閾値残業の割増率と、何分working超で残業扱いになるか。
昼休憩・法定休憩休憩の開始/終了時刻・必要時間。一定時間以上勤務すると自動付与。
最低勤務時間配置するならこの時間以上働かせる（短時間だけの呼び出しを防ぐ）。
1工程の最低配置時間一度入った工程になるべく連続で就かせる目安（細切れの工程移動を抑制）。
工程移動時の習熟ペナルティ休憩を挟まず別工程へ移った直後のスロットは生産性が低下する設定（オン/オフ・低下率）。

4. 最適配置の計算方法

計算は「2つの方針（案）」×「3つの計算エンジン」の組み合わせで行います。

4-1. 2つの方針（何を最適化するか）

案A：最速完了

作業を最も早く終わらせる配置

完了時刻を最小化します。多少コストがかかっても、とにかく早く終わらせたい日に向きます。

案B：最低コスト

期限を守りつつコストを最小化

締切を守れる範囲で人件費を最小化します。コスト重視の通常運用に向きます。

4-1b. 作業を終わらせる優先順位（残業の扱い）

どちらの方針でも、入庫・出庫それぞれの最終工程（棚入れ・梱包）まで作業を終わらせることを、 次の優先順位で目指します。

優先方針
① 最優先残業なし（定時内）で、前工程も含めてすべて終わらせる。
② 次善定時内で終わらなければ、残業して残業最大終了時刻までにやり切る。 ただし残業できない人を残業帯に配置することはありません（勤務条件で担保）。
③ 最後それでも終わらなければ、作業残を残して帰る（無理な配置はしない）。
工程完了期限（例：17:00）は「残業なしで間に合ったか」を判定するための目安です。 間に合わない場合でも、残業可能な人がいれば残業して作業を終わらせにいきます （処理を17:00で強制的に打ち切ることはしません）。

4-2. 3つの計算エンジン（どう解くか）

エンジンイメージ速さ解の質
簡易計算
(GREEDY)		 経験豊富な現場リーダーが直感で割り当てる方式。15分ずつ時間を進め、その瞬間に一番忙しい工程へ手を打つ。 ◎ 数秒△ 近似
焼きなまし法
(ANNEALING)		 解を少しずつランダムに変えて改善を繰り返す方式。良くなれば採用、時々あえて悪化も試して局所最適を脱出。 ○ 数十秒○ 良好
OR
(数理最適化)		 全組み合わせを数式で表し、数学的に最良解を探索。条件が許せば「これが最適」と証明付きで返す。 △ 数十秒〜数分◎ 最良
普段は簡易計算で素早く確認 → 納得いかなければ OR / 焼きなましで最良解を求める、という使い方が効率的です。

4-3. 連続化リペア（仕上げ処理）

計算後に「連続化リペア」という後処理が自動で走ります。これは、現実的でない 15分ごとの細切れな工程移動を減らす仕上げです。各工程の人数・処理量・コスト・完了時刻は 一切変えずに、「同じ人がなるべく同じ工程に居続ける」よう配置を組み替えます（下流に余力がある範囲で）。 昼休憩を挟んだ工程変更は自然なものとして許容します。

「計算ログ」の読み方（最重要）

項目意味
計算状態 最適解を確認 ✓＝最適だと証明済み（文句なし）／ 時間内の最良解＝良い解は出たが最適の証明は時間切れ（実用上は十分）／ 簡易計算（完了）＝高度計算が解を出せず近似手法に切替。
最適性ギャップ 「今の解」と「理論的な下限」の差(%)。0%＝最適を証明。小さいほど最適に近い。 ただし下限の精度が緩いと、解が良くてもギャップが大きく見える（特にコスト最小化や下界が緩い問題）。 数字が大きくても解が悪いとは限りません。
計算時間その案の求解に要した実時間。
検証パターン数探索した配置パターンの目安。0＝緩和した問題が一発で答えになり探索不要だった（正常）。
連続化リペア細切れ工程切替を何回から何回へ減らしたか。「削減なし」＝安全に減らせる切替が無かった（必要な切替か、余力不足）。
判断のコツ：ギャップの数字より、「作業完了時間」「総人件費」という実際の値で案を比べるのが実務的です。 例えば案Bの人件費が案Aより安ければ、コスト最小化はちゃんと機能しています。

6. 稼働グラフの見方

配置を選択するとシフト画面で勤務表を確認でき、その中の稼働グラフタブで処理の流れを可視化できます。 グラフは大きく2種類あります。

6-1. 人員配置（シフト表）

誰が何時にどの工程に就いているかを時間帯ごとに色分け表示します。連続化リペア後は、同じ人が同じ工程に 連続して就いている（細切れでない）ことが確認できます。

高橋
入荷 棚入れ ピッキング 仕分け 昼休憩
※ 同じ色が横に連続＝同じ工程に連続配置（細切れ移動が少ない良い状態）

6-2. 累積処理グラフ

各工程について「到着した量（届いた仕事）」と「処理した量」の累積を時系列で重ねて表示します。 2本の線が開いているほど、その工程で仕事が溜まっている（滞留している）ことを意味します。

シフト ／ 稼働グラフ ／ 累積処理
2本の線の縦の開き＝その時点の滞留量。最後に処理線が到着線に追いつく＝作業完了。

6-3. 工程間滞留量（バッファ）グラフ

工程と工程の間にどれだけ荷物が溜まっているか（処理残）を時系列で表示します。 点線は各工程のバッファ容量（上限）。実線がこの点線を超えると、溜めきれず溢れる危険のサインです。

シフト ／ 稼働グラフ ／ 工程間滞留量（バッファ）
山が高い＝その工程の前で荷物が溜まっている。点線（上限）を超えそうなら人員強化のサイン。

6-4. 工程別 稼働率テーブル

各工程について、時間帯（15分）ごとに「配置人員の最大処理能力」「実際の処理量」「稼働率」を表で確認できます。 稼働率は 処理量 ÷ 最大処理能力 で、人を配置していても作業が能力に満たなければ100%未満になります （整数の人数に対し作業量は端数になるため、100%未満は通常よく発生します）。

稼働グラフの活用： 「滞留が点線（容量）を超える工程」＝ボトルネック。そこに人を増やす／前工程を遅らせるといった 判断材料になります。稼働率テーブルでは、どの時間帯に人が余っている（稼働率が低い）かが分かり、 増員・減員の判断に使えます。連続化リペアは下流バッファに余力がある範囲でだけ配置を組み替えるため、 バッファグラフが「容量超え」しないことが保証されています。
