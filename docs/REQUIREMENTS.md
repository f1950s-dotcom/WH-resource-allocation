# 第Ⅰ部：要件定義

## 1. システム概要・目的

倉庫の1日の作業（**入庫ライン**・**出庫ライン**）について、時間帯ごとの物量と、
従業員のスキル・勤務条件から「**誰を・いつ・どの工程に配置するか**」を自動で最適化し、
**最速案**と**最低コスト案**の2案を提示・比較して、採用案のシフトを出力する。

- **利用者**：倉庫の人員計画担当者（シフト作成者）。
- **達成したいこと**：①当日の作業を必ず終わらせる、②できれば定時内、③人件費は最小、
  ④非現実的な15分刻みの工程移動を避ける。
- **1日の粒度**：時間帯は **15分スロット**で扱う。

## 2. 用語定義

| 用語 | 意味 |
|---|---|
| ライン種別 | 入庫(INBOUND)／出庫(OUTBOUND)。工程が属する系統 |
| 工程 | 荷受・検品・棚入れ・ピッキング・梱包 等の作業単位 |
| 根元工程 | 各ラインの最初の工程（物量が最初に発生する工程） |
| 末端工程 | 各ラインの最後の工程（棚入れ・梱包など）。締切の対象 |
| 物量 | 入庫/出庫の個数（時間帯別に登録） |
| 物量展開 | 物量を換算率で各工程の作業量に変換したもの |
| 習熟レベル | 工程ごとの熟練度(1-3)。生産性倍率に影響 |
| 作業残 | 当日に処理しきれなかった量 |
| 工程移動 | 同一人が隣接スロットで別工程に移ること |

## 3. 業務フロー（全体像）

```
[マスタ整備] 従業員・スキル・勤務条件・工程・接続・換算率・締切・システム条件
      ↓
[物量登録] 対象日の時間帯別 入庫/出庫 物量を入力
      ↓
[物量展開] 換算率で根元工程の作業量に変換（最適化直前に自動再生成）
      ↓
[最適化実行] エンジンを選び2案(最速/最低コスト)を計算
      ↓
[結果比較] カードで2案を比較 → 1案を採用
      ↓
[シフト出力] 人別/工程別シフト・稼働(進捗)グラフ・Excel出力
```

## 4. マスタ要件

各マスタについて「目的 / 管理項目（画面項目）/ 制約・補足」を示す。

### 4-1. 従業員マスタ
- **目的**：働く人の基本情報と人件費の基礎を管理する。
- **画面項目**：
  | 項目 | 型/入力 | 説明 |
  |---|---|---|
  | 氏名 | テキスト | 表示・シフト上の識別 |
  | 時給(円) | 数値 | 人件費・残業費計算の基礎 |
  | 有効/無効 | チェック | 無効は最適化対象外 |
- **補足**：時給が高い人を早く帰す等の最適化に使う。

### 4-2. スキル設定（習熟レベル）
- **目的**：誰がどの工程を、どれだけ速くできるかを管理する。
- **画面項目**：工程ごとに「対応可否」＋「習熟レベル(1/2/3)」。
- **制約**：スキルの無い工程には配置されない。レベルは生産性倍率（4-9）に直結。

### 4-3. 勤務条件（曜日別）
- **目的**：各人が「いつ働けるか」を曜日別に管理する。
- **画面項目**（**月〜日**の各行）：
  | 項目 | 型/入力 | 説明 |
  |---|---|---|
  | 出勤 | チェック | その曜日に働くか（未チェック＝休み） |
  | 開始 / 終了 | 時刻 | 勤務可能時間帯 |
  | 残業可 | チェック | 残業枠(定時後〜残業最大終了)に配置可か |
  | 最低労働(分) | 数値 | 配置するなら最低これだけ働かせる(0=無効) |
- **重要規約**：曜日は **月=0 … 日=6**（システム内部の Python weekday と一致）。
  画面の並びも**月始まり**にすること（日始まりにすると1日ズレる：第Ⅱ部の落とし穴参照）。
- **補足**：その曜日に「出勤」のある人だけが配置対象。土日に誰も出勤登録が無ければ**配置不可**（結果画面に明示）。

### 4-4. 工程マスタ
- **目的**：作業工程の能力とラインを管理する。
- **画面項目**：
  | 項目 | 型/入力 | 説明 |
  |---|---|---|
  | 工程名 | テキスト | 表示名 |
  | ライン種別 | 選択 | 入庫(INBOUND)/出庫(OUTBOUND) |
  | 基準生産性 | 数値(個/人時) | 標準1人が1時間で処理する個数 |
  | バッファ容量 | 数値 | 工程間に滞留できる上限（0=無制限扱い） |
  | 表示順 | 数値 | 画面の並び順 |
  | 有効/無効 | チェック | 無効は対象外 |

### 4-5. 工程接続
- **目的**：工程の前後関係（有向グラフ）を管理する。上流の処理結果が下流の作業を生む。
- **画面項目**：`from工程 → to工程` の対応（複数）。
- **制約**：根元工程＝どの接続の to にもならない工程。末端工程＝どの接続の from にもならない工程。

### 4-6. 物量換算ルール
- **目的**：入庫/出庫の物量を、各ラインの根元工程の作業量へ換算する。
- **画面項目**：
  | 項目 | 型/入力 | 説明 |
  |---|---|---|
  | 対象 | 選択 | 入庫(INBOUND)/出庫(OUTBOUND) |
  | 工程 | 選択 | 換算先の（根元）工程 |
  | 換算率 | 数値 | 物量×換算率＝作業量 |
  | 単位説明 | テキスト | 任意メモ |

### 4-7. 締切条件（工程完了期限）
- **目的**：末端工程を「残業なしで何時までに終わらせたいか」の目安を管理する。
- **画面項目**：工程 / 完了期限(HH:MM) / 有効。
- **制約**：**ハードな打ち切りではない**（ソフト。第Ⅱ部の優先順位を参照）。KPI表示と late ペナルティに使う。

### 4-8. システム条件（全体パラメータ）
- **目的**：最適化全体のルールをkey-valueで管理する。
- **主な画面項目**：
  | key | 既定 | 説明 |
  |---|---|---|
  | 残業割増率 | 1.20 | 残業スロットの割増 |
  | 残業閾値(分) | 480 | これを超える勤務が残業(=8h) |
  | 残業最大終了 | 20:00 | 残業可能者の最終終了時刻 |
  | 昼休み 開始/終了/分 | 11:30/13:00/60 | 昼休憩 |
  | 法定休憩 閾値/分 | 360/45 | 法定休憩 |
  | 工程移動ペナルティ 有効/率 | 1 / 0.30 | 移動直後スロットの生産性減 |
  | 1工程の最低連続配置(分) | 60 | 細切れ移動抑制の目安（完了時は不適用） |
  | 連続化リペアのコスト許容枠 | 0.03 | 切替削減に許容する総コスト増率(0=不許可) |

### 4-9. 習熟度→生産性
- **目的**：習熟レベルを生産性倍率に変換する。
- **画面項目**：レベル1=0.8 / 2=1.0 / 3=1.2（標準比）。

## 5. トランザクション要件

### 5-1. 物量登録
- **目的**：対象日の「その日の仕事の総量」を時間帯別に登録する。
- **登録内容・画面項目**：
  | 項目 | 入力 | 説明 |
  |---|---|---|
  | 対象日 | 日付 | 既定は**当日(JST)** |
  | 入庫/出庫タブ | タブ切替 | 種別ごとに入力 |
  | 時間帯ごとの物量(個) | 数値直接入力 | スロット別に入力 |
- **機能要件**：
  - **保存は入庫・出庫を一括**（保存時点で入力済みの両種別をまとめて保存）。
  - **CSVインポート**で時間帯・物量を一括投入可能。

### 5-2. 物量展開
- **目的**：物量を各根元工程の作業量に変換して確認する。
- **画面項目**：対象日の展開結果（工程×スロットの作業量）。
- **機能要件**：**最適化実行の直前に必ず自動再生成**（登録変更との不整合防止）。

### 5-3. 最適化実行
- **目的**：2案（最速/最低コスト）を計算する。
- **画面項目**：対象日 / **計算エンジン選択**（下表）/ 実行ボタン / 進捗表示。
  | エンジン | 位置づけ |
  |---|---|
  | GREEDY | 高速・近似（MIP不使用） |
  | ANNEALING | MIP(CBC)＋焼きなまし補正 |
  | ORTOOLS | MIP(CBC)＋CP-SAT席選択 |
- **機能要件**：非同期実行。**エンジンを変えると結果が並存**し比較できる。計算中は進捗をポーリング表示。

## 6. 結果表示要件（何を・どう見せるか）

### 6-1. 最適化結果一覧（案の比較）
- **エンジン別にグルーピング**し、各エンジンで **案A(最速)／案B(最低コスト)** のカードを並べる。
- **カード表示項目**：
  | 表示 | 内容 |
  |---|---|
  | 案ラベル | 案A：最速完了 / 案B：最低コスト |
  | 計算状態 | 最適／時間内の最良解(残ギャップ%)／簡易計算（意味の分かる日本語） |
  | 作業完了時間 | completion_time |
  | 出社人数 | 配置人数 / 出社可能人数 |
  | 総コスト・残業費 | 金額 |
  | 工程移動回数 | 回 |
  | 作業残 | なし / あり（N個） |
  | 期限遵守 | ✓遵守 / ✗定時超過 |
  | 操作 | [詳細を見る] [この案を選択] |
- **特記**：その曜日に配置可能な従業員が0人のとき、**「配置できる従業員がいない」バナー**を表示。

### 6-2. 結果詳細（ガントチャート）
- **統計サマリ**：期限遵守 / 総人件費 / うち残業費 / 工程移動回数 / 作業残（あり N個・なし）。
- **ガント**：**人員 × 15分スロット**の表。セルは**工程で色分け**、昼休憩・法定休憩を区別、右端に**人別費用**。工程色の凡例を表示。

### 6-3. シフト画面（採用案）
- **ヘッダ**：対象日、残業費、**Excelダウンロード**。
- **3タブ**：
  1. **人別シフト**：人員×スロット（各セルの担当工程）。
  2. **工程別シフト**：工程×スロット（そのスロットに就く人員名）。
  3. **稼働グラフ（進捗）**：以下を表示。
     - 工程別の **発生量 / 処理量 / 処理残 / 最大処理能力 / 稼働率**（＝処理量÷最大処理能力、人未配置は—）。
     - **工程間滞留量（バッファ）グラフ**：処理残の推移（実線）。
     - 入庫系・出庫系それぞれの**累積処理グラフ**。
- **重要**：進捗の数値は**バックエンドの単一フロー計算**を唯一の真実とし、フロントは表示のみ（第Ⅱ部の落とし穴）。

### 6-4. Excel出力
- 採用案のシフト（人別/工程別）をExcelブックで出力する。

## 7. 非機能要件

| 項目 | 要件 |
|---|---|
| タイムゾーン | 日付・曜日判定は**日本時間(JST)**で統一 |
| 認証 | 既定は認証なし（URL共有で利用）。機微データなら前段に簡易認証を検討 |
| 性能 | 重い日でも簡易計算に転落しにくいこと（時間・隔離・フォールバックで担保） |
| 可用性 | 計算はバックエンドで実行。多コアで案を並列、CPU制約環境では逐次も可 |
| データ永続化 | SQLite（無料クラウドは揮発。永続化はボリューム/外部DB） |
| 拡張性 | 全体ルールは**システム条件(key-value)**で変更可能に |

## 8. アーキテクチャ

クライアント・サーバー構成。重い計算は**すべてバックエンド**（FastAPI/Python）で実行し、
ブラウザ(React)は表示のみ。MIP求解は**forkした子プロセスに隔離**し暴走・クラッシュから本体を守る。
（→ `DESIGN.md` 第2章 図）

| 要件 | テーブル |

| 従業員/スキル/勤務条件 | `employees` / `employee_process_skills` / `employee_work_conditions` |

| 全体ルール/習熟度率 | `system_conditions` / `skill_level_productivity_rates` |

## 10. 最適化計算の処理ロジック・仕様（★繰り返し検証し最終的に落ち着いた内容）

要件（4章の目的①〜④）を、次の確定仕様で満たす。

### 10-1. 優先順位（要件①②③の実現）
目的関数の重みを桁で階層化して表す：
**作業残(short) ≫ 締切超過(late) ≫ 残業割増 ≫ 通常コスト**。
- 案A(最速)=`MAKESPAN`：在庫時間（各時刻の滞留量総和）を最小化＋`1e8·short`。
- 案B(最低コスト)=`COST`：`cost + 1e3·late + 1e5·short`。

### 10-2. ソフト制約化（要件①「必ず終わる」の実現）
- 「全量処理」「締切」「最低連続配置」を**ハード制約にしない**。
  - 未処理 `short` を許容し重罰（空配置＝常に実行可能でINFEASIBLE回避）。
  - 締切は late ペナルティ（残業枠が空いていれば残業してでも終わらせる）。
  - 最低連続配置はMIPに入れず、**連続化リペア**で後処理（要件④）。

### 10-3. フロー・シミュレーション（要件と進捗表示の一貫性）
能力 `= 基準生産性 × 習熟度率 × 工程移動係数 × 0.25(15分)`、
`throughput = min(残, 能力)`、下流へ **15分ラグ**で `throughput×換算率` を伝播。
**この単一ロジックを最適化・完了時刻・進捗グラフで共有**する（→ 6-3、落とし穴）。

### 10-4. 連続化リペア（要件④の実現・3フェーズ）
求解後に15分刻みの細切れ切替を減らす。
- F1：同一スロットで2人の工程入替（総未処理量が悪化なら丸ごと取消）。コスト不変。
- F2：直前工程へ付替（未処理量・締切が非悪化のみ）。コスト不変。
- F3：**コスト許容枠**(`repair_cost_budget_rate`)以内で担当を別人へ入替。工程別人数は維持。

### 10-5. 時間管理・隔離・フォールバック（要件「簡易計算に落ちにくい」）
- 内部制限：`clamp(60 + 整数変数数/40, 60, 600)`秒、早期終了はギャップ1%。
- ハード強制終了：**700秒**で子プロセスkill →`None`→簡易計算。
- 2案は**独立スレッド/セッション/タイマー**で並列。CPU制約環境では逐次も選択。

### 10-6. 詳細擬似コード（全アルゴリズム）
物量展開・`_run_flow`・`_simulate_fixed`・`calc_score`・進捗グラフ`compute_flow_report`・
昼休み割当・選定キー・焼きなまし/CP-SAT/帰宅処理・`run()`順序は
**`DESIGN.md` 第15章**に実アルゴリズムとして記載。再構築時はそちらを一次資料とする。

## 11. 修正履歴・最終結論・落とし穴（★同じ試行錯誤を繰り返さないための記録）

以下は「作り直すと再発しやすい」決着点。全一覧は `DESIGN.md` 第13章。

| 領域 | 最終結論（値・式） | 再発防止 |
|---|---|---|
| 全量処理 | ソフト化 `short`＋重罰 | 「必ず終わる」は制約でなくペナルティ |
| 最低連続配置 | MIPに入れず**リペア後処理** | 整数塊制約はCBCを暴走させる |
| 締切 | ソフト`late`＋優先順位 | 残業枠が空けば残業して終わらせる |
| makespan | **在庫時間(滞留総和)最小化** | big-M最遅スロットはNOT_SOLVED |
| 未処理重み | COST:1e3/1e5、MAKESPAN:1e8 | 桁を上げすぎると数値精度悪化 |
| ソルバー | **子プロセス隔離＋700秒kill** | 制限無視・クラッシュ前提で監視 |
| 時間上限 | 式 `60+n/40`（上限でなく式） | 実効値を実測してから調整 |
| 並列 | 独立実行、CPU競合注意 | 一方が他方を打ち切らない設計 |
| 出社人数 | **マスタ確定値**で固定 | 途中で変わる配列で数えない |
| 最低コスト逆転 | **単位処理コスト**で選定 | 時給順で選ばない |
| 曜日 | **月=0**に統一（月始まり表示） | JSの日=0と混ぜない |
| 日付 | **JST** | UTC `toISOString()` を使わない |
| 無人日 | 明示バナー | 候補0人を黙って空表示しない |
| 進捗の残 | **単一フロー計算を全所で共有** | 画面と最適化で別計算しない |
